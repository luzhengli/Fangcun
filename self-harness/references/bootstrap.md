# 初始化

目标是最小骨架，不是全套模板。预填的通用文档没人读，还占上下文。

## 步骤

1. **先看已有的。** `harness init --root <项目>`：探测入口文件、状态、待办、决定、检查命令。项目已经有 PLAN.md、tasks.json、JOURNAL.md 之类的，就在配置里指过去，不另建一份。
2. **补五样，缺哪样补哪样：**
   - 入口文件（AGENTS.md；Claude Code 用 CLAUDE.md 软链到它）：项目是什么、去哪读什么、最硬的几条规则、检查命令、交流语言。模板见 `templates/entry.md`，控制在预算内。
   - 状态文件：只写判断。模板见 `templates/status.md`。
   - 待办：任何格式都行，要人处理的单列一节。
   - 决定：人定的事记原话和日期。
   - 摩擦记录：一个标题下的复选列表，可以放在流程文档末尾。
3. **第一个判官是检查命令。** 没有一条能跑通的「格式 + 类型 + 测试 + 构建」命令，先补它，其余都往后放。
4. **人确认后** `harness init --write`：只写 `.harness/` 下的配置和两份空清单，已有的不覆盖。然后手补 `config.json` 里探测不到的：`friction`、`queues`、`ports`、`boundaries`。
5. **安装 skill**：见 `adapters/`。
6. **列一版判官清单**（`oracles.md`），不求全，先把「无」和「人判」的维度列出来。

## 不要做

- 不要一次性建十几个文档。
- 不要把别的项目的规则抄过来。规则要有本项目的证据。
- 不要覆盖已有文件。要改，先给人看差异。
