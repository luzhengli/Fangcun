## 2026-11-14 工程骨架的选型

- 人的原话：「在正式实现前，当前先基于方案和原型，以架构师视角生成项目的环境配置，代码框架、模块，打好基础，不用具体实现。后续将在这个基础上，基于产品设计和原型进行实现。」
- 技术栈（Rust 内核 + Tauri 2 + React）是人在 9.2 定的。下面都是 Agent 定，可逆，理由写在 `docs/ARCHITECTURE.md`：
  - **仓库布局**：一个 Cargo 工作区加一个 pnpm 工作区。`crates/` 放内核和命令行，`apps/desktop/` 放外壳和界面，`adapters/` 放适配器。
  - **内核只有一个门面 `Kernel`**，一个用例一个方法。内核是同步的，不带异步运行时，外壳在阻塞线程里调。
  - **只读用类型守住**：`Access::ReadOnly` 下写入用例直接报错，M0 的外壳和命令行都这样打开内核。写入用例一律先返回变更计划，只有 `apply` 落盘。
  - **类型从 Rust 导出到 TypeScript**，用 ts-rs，产物提交进仓库，CI 检查一致。没选 tauri-specta，它还在候选版本。
  - **适配器是内置的 TOML**，结构体拒绝不认识的字段，格式和数据必须一起改。内容留空，等 M0-02 对照当期文档核实，不凭记忆填。
  - **`~/.fangcun` 的子目录名**：`library/`、`git/`、`index.sqlite`、`snapshots/`、`adapters/`。文档只定了 `bundles/` 和 `journal`。
  - **命令行的退出码**：1 运行失败，2 参数错误，3 尚未实现。
  - **前端**：Vite、React 19、TypeScript、React Router（哈希路由）、TanStack Query 管内核数据、zustand 管窗口状态、CSS Modules 加「墨格」token，不用 Tailwind。Biome 做格式和 lint，Vitest 做测试。
  - **token 不手抄**：`tokens.css` 由脚本从原型生成，测试逐项比对。深色用系统的配色偏好切换，不用原型的 `.dark` 类。
  - **窗口**：标题栏用 Overlay，窗口按钮由系统画在 40px 的工具栏里。默认 1280×800，最小 720×640。
  - **CSP 只允许本地资源**，界面发不出外部请求。原型里的 Google Fonts 没有搬进来，靠系统字体。
  - **占位**：包标识 `app.fangcun.desktop`、显示名 `Fangcun`、应用图标。都要人定，见 BACKLOG D-16、D-17。
  - **没有加许可证字段**，等 D-09。
- 没定的选型（SQLite、git、文件监听、钥匙串、token 估算口径、内容哈希、时间库）列在 `docs/ARCHITECTURE.md` 末尾，到用的那一步再定。
- 发现的设计缺口，要人定或要先补进设计文档：M0 能不能写 `~/.fangcun`（D-15）；`fangcun.lock` 的格式、套装文件的内容、按项目停用的写法（BACKLOG M1-pre）。
