# 方寸 Fangcun：Agent 环境管理器 · 产品设计方案

> v0.6 · 2026-11-14 · 第 6 节是界面的要求，原型按它画，2026-11-14 核对过没有已知不一致；第 9 节的十四件待定事项已全部确认
> 产品名「方寸 Fangcun」，寓意「方寸之间，上下文井然」。

---

## 1. 结论先行

**一句话定位**：方寸是 Agent 上下文的「包管理器 + 环境管理器」，配一个好用的 Mac 桌面界面。它之于 Skills、MCP、指令文件，相当于 uv 或 mise 之于 Python 依赖与运行时。

**三个核心主张**

1. **Agent 读取的目录是构建产物，不是源。** `.claude/skills`、`.mcp.json`、`CLAUDE.md` 这些位置今天被人手工编辑、到处复制。方寸把它们降级为「由唯一来源生成的输出」。
2. **以项目为中心，而不是以资产库为中心。** 每个项目声明自己需要什么、锁定到哪个版本。全局层尽量薄。
3. **先看见，再管理。** 任何时刻都能回答「这个项目里的 Agent 此刻到底加载了什么、花了多少上下文、谁覆盖了谁」。

**MVP 是一个闭环**：看见 → 收编 → 声明 → 同步 → 更新。覆盖 Skills、MCP、指令文件三类资产，首批完整支持 Claude Code 与 Codex。

**关于命名**：业界说 harness 多指 Agent 运行时本身，例如 Claude Code、Codex。你描述的是运行时之上「可配置、可移植的那一层」。本文把它叫做 **Agent 环境**（项目级的整体）和 **上下文资产**（其中的每一件）。「project harness」作为口语别名保留。

## 2. 痛点深挖

### 2.1 你的机器就是证据

写方案前我只读扫描了本机，结果如下。

| 观察 | 事实 |
|---|---|
| Agent 工具数量 | 主目录下有 7 个工具的配置目录：Claude Code、Codex、Cursor、Gemini、opencode、Copilot、Windsurf。项目里还出现了 Trae。 |
| 同一 skill 的副本 | `project-harness` 在 5 个项目里各有一份。4 份内容相同，`evals_studio/.trae` 里那份已经分叉。 |
| 没有唯一来源 | `luyao-skills`、`my-skills`、`agent-skill`、`harness` 四个仓库里存放着内容相同的 skill。哪个是正本无从判断。 |
| 各工具分发不一致 | `~/.agents/skills` 有 31 个 skill。Claude Code 只链接了其中 16 个，Windsurf 有 20 个，Codex 有 3 个。 |
| 全局污染 | 本次会话开在一个空目录里，16 个飞书 skill 的描述仍全部进入了上下文。 |
| 版本停滞 | 全局锁文件最后修改于 7 月 5 日，而 skills 目录 11 月 11 日还在变动。锁与实际已脱节。 |
| MCP 配置分散 | 至少四处各自为政：`~/.claude.json`、`~/.codex/config.toml`、`~/.gemini/settings.json`、opencode 配置。 |

### 2.2 你提出的痛点

| 痛点 | 本质 |
|---|---|
| 不同项目要求不同的资产与版本 | 缺少项目级的需求声明与版本锁定 |
| 用户级与项目级冲突、无效占据上下文 | 作用域只有「全局 / 项目」两档，且生效结果不可见 |
| 版本经常得不到更新 | 资产没有来源记录，更新没有入口也没有提醒 |
| 一份 skill 复制得到处都是 | 没有唯一来源，复制是唯一的分发手段 |

### 2.3 你还没提到、但同样要命的痛点

1. **生效上下文不可见。** 托管层、用户层、项目层、本地层、插件层、子目录指令层层叠加，每个工具的优先级规则还不一样。没有人能一眼说出「最终生效的是什么」。
2. **上下文预算税。** 每个 skill 的名称与描述常驻上下文，每个 MCP 服务的工具定义也要占位，指令文件全文加载。全局装一个，所有项目都缴税。
3. **多工具碎片化。** 指令文件有 `CLAUDE.md`、`AGENTS.md`、`GEMINI.md`。MCP 配置有 JSON 也有 TOML。同一份意图要维护 N 种格式。
4. **原地修改无法回流。** Agent 工作时经常顺手改进项目里的 skill 副本。这些改进留在副本里，永远回不到来源，也到不了其他项目。
5. **供应链与信任。** Skill 带脚本，hook 执行任意命令，MCP 服务拿着你的凭据运行。上游一次静默更新就能改变 Agent 行为。
6. **密钥裸奔。** MCP 配置里的 API Key 以明文存在，随复制扩散，偶尔还被提交进 git。
7. **不可复现。** 新同事、新电脑、git worktree、云端或 CI 里的 Agent，都拿不到和你一样的环境。「在我的 Agent 上是好的」。
8. **隐式依赖。** Skill 依赖某个 CLI、某个 MCP 服务、某个环境变量，却从不声明。缺了就静默失效。
9. **个人与团队混在一起。** 哪些该提交给团队、哪些只是个人偏好，现有机制没有清晰的分层。
10. **只进不出。** 没有使用数据，不知道哪些 skill 从未被触发。资产只增不减，越积越乱。
11. **无法回滚与试验。** 改了一个 skill 效果变差，没有后悔药，也没法对比。
12. **作用域太粗。** 真实需求是「我所有前端项目」「这个客户的项目」「工作与个人」。全局与项目两档表达不了。

### 2.4 五个根因

所有痛点可以归到五个根因，产品的五个支柱一一对应。

| 根因 | 对应支柱 |
|---|---|
| A. 没有唯一来源 | 资产库 |
| B. 项目需求没有声明 | 项目清单与锁 |
| C. 生效结果不可见 | 生效上下文视图 |
| D. 目标格式碎片化 | 适配器与物化 |
| E. 没有生命周期 | 更新、回滚、回流 |

这其实是一个被解决过很多次的问题。Python 从全局 site-packages 走到 virtualenv 加锁文件。Node 从全局安装走到 `package.json`。Agent 上下文今天正处在「全局 site-packages」阶段。

## 3. 现状与竞品

以下判断基于各项目的自述页面，我没有逐一试用。这个领域每月都在变，立项前建议实测前三名。

| 类别 | 代表 | 解决了什么 | 留下的空白 |
|---|---|---|---|
| Skill 命令行 | [vercel-labs/skills](https://github.com/vercel-labs/skills) | 安装、软链到多个工具、全局锁与项目锁 | 只管 skill。锁里只有哈希没有版本语义。没有可见性。[删除后锁残留](https://github.com/renovatebot/renovate/discussions/41841)等粗糙处仍在 |
| Skill 桌面库 | [skills-manage](https://github.com/zhaikong/skills-manage)、[Skills Manager](https://skillsmanager.dev/)、[Skill Desktop](https://skill-desktop-labs.github.io/skill-desktop-landing/)、[Agent Desk](https://agentdesk.sh/) | 一个库分发到几十个工具 | 以库为中心，本质是「全局分发器」。项目级版本锁定与生效视图薄弱 |
| MCP 管理器 | [MCP Linker](https://mcp-linker.milisp.dev/)、[Claude Code Tool Manager](https://github.com/tylergraydev/claude-code-tool-manager)、[mTarsier](https://mtarsier.com/) | 多客户端 MCP 配置同步，部分支持按项目指派 | 与 skill、指令割裂。密钥与复现不是重点 |
| 锁与体检命令行 | [skillock](https://github.com/quantz8a/skillock)、[agent-skills-cli](https://github.com/Karanjot786/agent-skills-cli) | 锁文件、token 预算、冲突检测 | 只有命令行，各管一段，没有闭环 |
| 原生机制 | Claude Code 插件与市场 | 打包分发、按项目启用 | 只在单一工具内有效 |

**空白在哪里**：现有产品几乎都在回答「怎么把一个库同步到 N 个工具」。没有产品把这四件事合在一起：

- 以项目为中心的声明与逐项目版本锁定
- 跨资产类型统一管理：skill、MCP、指令
- 生效上下文的透视与预算
- 副本修改的回流

**必须正视的事实**：赛道已经拥挤。方寸的差异不能靠功能清单，要靠「项目中心的闭环」和体验质量。[agentskills.io 的实现指南](https://agentskills.io/client-implementation/adding-skills-support)已约定项目级覆盖用户级并建议提示用户，说明「遮蔽可见性」是公认需求但尚无好的界面。

## 4. 核心理念与概念模型

### 4.1 一条流水线

```
来源 Source ──▶ 资产库 Library ──▶ 清单 + 锁 ──▶ 物化 Sync ──▶ 生效视图 X-Ray
(git/本地/市场)   (唯一正本，带版本)   (项目声明)     (写入各工具原生位置)   (看见结果)
                        ▲                                  │
                        └────────── 回流 Promote ◀──────────┘
                                 (副本被改，决定去留)
```

### 4.2 七个概念

| 概念 | 含义 | 类比 |
|---|---|---|
| **资产 Asset** | 一件可被 Agent 读取的东西。MVP 含三类：Skill、MCP 服务、指令文件 | 包 |
| **来源 Source** | 资产的出处：git 仓库、本地开发目录、公开市场 | 注册表 |
| **资产库 Library** | 本机唯一正本，按内容寻址存储，保留每个版本 | 包缓存 |
| **套装 Bundle** | 一组常一起用的资产，起个名字给多个项目复用，例如「飞书办公」「前端基线」 | 依赖组 |
| **清单 Manifest** | 项目根目录的 `fangcun.toml`，声明目标工具、资产、版本约束 | `package.json` |
| **锁 Lock** | `fangcun.lock`，记录解析出的确切提交与内容哈希 | 锁文件 |
| **物化 Sync** | 把解析结果写进各工具的原生位置，并记录哪些文件归方寸管 | 安装 |

### 4.3 作用域：从两档变四层

```
全局基线   尽量薄，只放真正每个项目都要的
   ▼
套装       按项目类型、客户、场景复用
   ▼
项目清单   提交到 git，团队共享
   ▼
个人覆盖   fangcun.local.toml，不提交，只属于你
```

下层覆盖上层。覆盖关系在界面里永远可见，不靠记忆。

这是方寸声明的规则。落到工具时，同名项谁生效按工具自己的规则，生效上下文视图如实显示，不替工具改写：

- Claude Code 的同名 skill 是上层优先（官方文档：个人盖过项目），与这里相反；同名 MCP 是个人 > 项目 > 全局，整条取用。
- Codex 的同名 skill 不合并，两份都加载；同名 MCP 项目层赢，按字段合并。

工具规则与方寸相反时，物化不自动移动上层的同名项：全局目录是所有项目共用的，移走它，没覆盖它的项目也读不到了。方寸把这种情况标为「同名冲突」，给出「转成套装」「从全局移除」两个动作，都先出变更计划，列出受影响的项目，由人决定。

### 4.4 版本是什么

Skill 规范本身没有版本字段。方寸定义版本为「来源提交 + 内容哈希」。有 git 标签就显示标签，没有就显示日期与短哈希。每项资产有两种跟随方式：

- **固定 Pin**：锁死在某个版本，只有手动才变。
- **跟随 Track**：跟着某个分支，有新版本时提醒，确认后才更新。

### 4.5 你的例子怎么解

项目 A 要 Skill A v1、Skill B v1。项目 B 要 Skill B v2、Skill C v1。

- 资产库里 Skill B 的 v1 与 v2 并存，各一份。
- 项目 A 的清单固定 B 到 v1，项目 B 固定到 v2。各自物化进自己的项目目录。
- 全局层不安装 B，于是不存在覆盖干扰。
- 上游出 v3 时，活动页的待处理里出现一条「可更新」，列出这两个项目，各自决定是否升级。

### 4.6 六条设计原则

1. **不发明运行时。** 只写各工具的原生位置。卸载方寸后一切照常工作。
2. **文件即真相。** 清单与锁是纯文本，可读、可提交、可审查。界面只是它们的编辑器。
3. **预览先于写入。** 任何落盘动作先出变更计划，确认后才执行。
4. **一切可撤销。** 每次同步都是一个快照，可一键回退。
5. **只动自己的东西。** 记录所有权。共享文件按键合并，绝不整文件覆盖。
6. **本地优先。** 不需要账号，默认不上传任何数据。

## 5. MVP 核心功能

MVP 的范围是六项能力。每项都直接对应第 2 节的痛点。

### F1 全盘体检与收编

- 扫描主目录与你登记的项目目录，识别所有工具的 skill、MCP、指令文件。
- 按内容哈希归并：哪些是同一份的副本、哪些已经分叉、哪些来源未知。
- 输出体检报告，每条发现配一个可撤销的一键动作。
- 「收编」把选中的资产移入资产库，原位置替换为受管链接，事前自动备份。内容相同的副本归为一个版本，分叉的另存为独立版本，每个位置链到自己那一版，Agent 读到的内容不变。只换工具目录里的实体目录；软链到本地 skill 仓库的不动，未登记项目里的不在写入范围、跳过并提示。收编不改清单，换过的位置记在本机的收编台账；来源未知的项在资产库补上来源后再写进清单（9.3）。

**验收**：从安装到看到体检报告不超过两分钟，全程零配置。在你的机器上应能直接报出「project-harness 有 5 份副本，其中 1 份已分叉」。

### F2 资产库

- 按内容寻址存储，多版本并存。
- 三种来源：git 仓库、本地开发目录、公开 skill 市场。公开市场指 [skills.sh](https://skills.sh)，只用来搜索和发现：选中的 skill 在清单里写成它所在的 `github:owner/repo`，锁照常记提交和哈希，不另设来源类型。skills.sh 没有可用的搜索接口时，M1 只支持粘贴 skills.sh 链接或 `owner/repo`。
- 本地开发目录是「活链接」：你在自己的 skill 仓库里改，登记为开发模式的项目立即可见。开发模式写在个人覆盖 `fangcun.local.toml` 的 `[dev]` 里，这些项在本机直接软链到本地来源目录，不经资产库、不改锁、不报漂移，队友仍按锁里的版本（7.4）。
- 本地来源在清单里只写名字，例如 `local:luyao-skills`；名字对应的目录记在本机的 `~/.fangcun/sources.toml`，第一次从某个目录加资产时自动记下。别的机器上没有这个名字时提示「本机没有来源 luyao-skills」，让人选目录，或按锁从资产库还原。
- 一个仓库里有多个 skill 时，按名字找：`SKILL.md` 的 `name` 等于清单里的键的那个目录，和 `skills` 命令行的找法一致。找到多个就报错，让人在清单里加 `path`。找到的路径记进锁。
- 每项资产显示：来源、版本历史、被哪些项目使用、预估 token 成本、是否含脚本。
- 按类型与来源筛选，来源按本地开发、GitHub、npm、待收编分组。

**验收**：同一 skill 在本机只有一份正本。任一资产都能回答「从哪来、谁在用、哪个版本」。

### F3 项目环境：清单与锁

- 登记项目后生成 `fangcun.toml` 与 `fangcun.lock`。登记有三个入口，都调内核同一个用例、都先出变更计划：命令行 `fangcun init --from-existing`；侧栏「近 30 天的项目」里选中未登记的目录，检查器点「登记」；侧栏「添加项目…」选一个目录。已经带 `fangcun.toml` 的仓库（例如克隆下来的），一经发现就自动登记，按现有清单与锁同步，不再反推。
- 登记时问一次物化方式（9.2「默认物化方式」）：个人项目建议链接；项目 git 历史里有两位及以上提交者（`[bot]` 不算）时建议入库。选的写进清单的 `mode`。
- 登记表是本机的 `~/.fangcun/projects.toml`，纯文本，每个项目一节，记路径、登记时间这类本机信息，不提交。物化记录照旧在 `~/.fangcun/state/`（7.4）。
- 声明目标工具、套装、资产与版本约束、物化方式。
- `fangcun.local.toml` 承载个人覆盖，自动加入 `.gitignore`。清单、锁、套装文件、个人覆盖的写法见 7.4。
- 能从现状反推：对已有项目，直接把当前目录里的资产反向生成清单。规则如下，查不出来源、做不到的项都写在变更计划上方的提示里：
  - **目标工具**：项目里有这个工具的痕迹（它的 skill、MCP、指令文件、其他加载项），或近 30 天在这个项目用过它。只算完整支持的工具，一个都没有时全写。
  - **Skill**：只写查得出来源的。依次看项目的 `skills-lock.json` 与全局锁记的来源、软链指向的本机目录（记成 `local:` 来源）、资产库里内容一样的那一项。GitHub 来源沿历史找内容一样的提交锁定，清单里不写版本，跟随默认分支；对不上时锁定最新版并提示。来源未知的不进清单，留在原处照常生效，收编（F1）后再加。
  - **MCP**：项目层的服务写进 `[mcp]`。`env` 里的明文密钥不抄，改写成 `secret:` 引用，计划里标红。
  - **指令文件**：一份只是对另一份的引用（`@AGENTS.md` 或软链）时，被引用的是正本、它是镜像；两份各自独立时正本取 `AGENTS.md`，另一份不设为镜像。
- 能导入导出 `skills-lock.json`，与现有命令行生态互通。导入在登记时：项目里有 `skills-lock.json` 的，`fangcun init --from-existing` 按它记的来源反推，旧版（v1）的哈希先校验再换算（7.4）。导出用 `fangcun export skills-lock`：把锁里 GitHub 来源的项写成新版（v2）`skills-lock.json`，原文件里方寸不管的项原样留下，走变更计划。

**验收**：新机器上克隆仓库，一条命令或一次点击即可还原完全相同的环境。

### F4 物化同步与漂移处理

- 先出变更计划，列出将新增、修改、删除的每个文件。
- 两种物化方式，按项目选择：
  - **链接**：项目目录里是指向资产库的软链，零重复，适合个人项目。
  - **入库**：实体文件提交进仓库，同事与云端 Agent 无需安装方寸，适合团队项目。
- 多工具去重：实体只放一份在 `.agents/skills`，其他工具目录用相对软链指过去。
- 目标位置已有不归方寸管的副本时也替换：内容和锁定版本相同的写「改由方寸管理」，不同的在计划里标橙，替换前进快照，回滚能找回（9.3）。
- 链接模式的受管路径、个人覆盖与开发模式的项、`fangcun.local.toml` 写进 `.gitignore` 里方寸管理的一段，带起止标记，块外的行不动（9.3）。
- MCP 写进目标工具的项目配置，按键、按字段合并，别的键、字段和顺序不动。
- CI 里用 `fangcun --yes sync --frozen`：锁与清单不一致就失败、不写文件；一致就按锁同步。
- 文件监听发现受管副本被修改时，给三个选择：**回流**到来源、**丢弃**修改、**分叉**为项目专属（9.3）：
  - 链接模式下副本是指向资产库正本的软链，改到的是正本，链到它的项目都会报漂移。处理时改过的内容先进快照，正本按锁从来源取回原版；本地来源没有提交时原版取不回，只能回流或分叉。
  - **回流**只对 `local:` 来源：修改写回来源目录，在来源仓库的当前分支上提交，本项目的 `pin` 改成新提交。同样用这一项的其他项目由上游检查列进「可更新」，逐个决定。来源仓库里的提交不随回滚撤销。
  - **丢弃**：恢复为锁定的版本，修改进快照，回滚能找回。
  - **分叉**：清单和锁里去掉这一项，`.agents/skills/<名称>` 变成项目自己的实体目录、提交进仓库，方寸不再管它；链接模式的正本还原成原版。

**验收**：同步不触碰任何非受管文件。Agent 在项目里改了 skill，五秒内出现漂移提示。

### F5 生效上下文视图

这是方寸的招牌界面，也是与竞品最大的区别。

- 按「项目 × 工具」展示 Agent 实际加载的全部内容，标明每一项来自哪一层。
- 标出被覆盖、重名冲突、重复加载、来源未知。
- 上下文地图（6.3）：常驻成本与按需成本分开估算，并标明是估算值。对照的项目预算写在 `fangcun.toml`，没写时 20k（7.4）。
- MCP 的常驻是工具定义，要启动服务才读得到。M0 不启动任何进程，MCP 标「未估算」，地图上 MCP 的块为 0，旁边写「MCP N 个未估算」。M1 提供显式的「试启动并测量」动作，结果缓存。
- 同名项谁生效按工具的真实规则（4.3）。
- 就地操作：从全局降级为按项目、在本项目停用、查看覆盖它的是谁。
- 每一项都能看到：为什么是这个状态、在哪一层声明、占多少常驻、写入了哪些文件、最近活动。
- 插件、hook、子代理、斜杠命令在 MVP 里只看不管：逐行展示，不提供操作，不计入预算。

**验收**：对任一项目，十秒内回答「加载了什么、谁覆盖了谁、常驻占多少」。

### F6 更新、回滚与密钥

- 更新：列出有新版本的资产与受影响项目，展示差异，脚本与命令变更高亮警示。不单独设「更新中心」页面，入口在活动页的待处理，处理在项目页检查器。
- 上游检查：桌面应用启动时查一次，之后只在手动触发时查（`fangcun update --dry-run`）。跟随分支的项取那个分支最新的提交，其余取默认分支最新的提交；内容哈希和锁里的不同就是「可更新」，新出现的版本各记一条待处理（9.3）。
- 可逐项目升级，也可批量升级。每次同步留快照，一键回滚。
- 快照只存这次变更计划要动的每个路径的原样：整文件存进 `~/.fangcun/snapshots/objects/`，按内容哈希去重；每个快照一份 TOML，记路径、哈希、权限、软链目标，以及「原来不存在」。回滚按它逐字节还原。保留期见 6.7「快照」。
- MCP 密钥存入 macOS 钥匙串。提交进仓库的配置只含环境变量引用，明文只落在不提交的本地配置里（9.3）：
  - Claude Code：`.mcp.json` 的 `env` 写 `${GITHUB_TOKEN}`；带明文的整条写进 `~/.claude.json` 里这个项目那一节（个人层，同名时优先、整条取用）。
  - Codex 项目里没有不提交的配置：`.codex/config.toml` 只写 `env_vars = ["GITHUB_TOKEN"]`，从启动 Codex 的环境里取，方寸不替它落明文，同步计划里写一条说明。
  - 钥匙串里缺这个密钥时，用到它的服务不同步，已经写过的不删。
  - 值只在命令行录入（`fangcun secret set`），界面不放输入框；检查器在钥匙串缺这一项时给出命令。登记时反推清单改写成 `secret:` 引用的明文，一并存进钥匙串。
  - 快照里方寸写在个人层的明文换成占位，回滚时从钥匙串取回；钥匙串里已经没有时回滚挡住。
- 体检会报告「已提交文件里有明文密钥」。

**验收**：升级前必能看到差异。回滚后磁盘状态与上一快照逐字节一致。

### 配套：命令行

桌面应用与命令行共用同一个内核。命令行让 CI、云端 Agent、worktree 无需界面也能还原环境。

```bash
fangcun doctor                # 只读体检
fangcun init --from-existing  # 登记项目，从目录现状反推清单与锁
fangcun status                # 当前项目的同步状态与漂移
fangcun add <资产>             # 加入清单
fangcun adopt <资产>           # 收编进资产库
fangcun lock                  # 重新解析清单，更新锁
fangcun export skills-lock    # 把锁导出成 skills-lock.json，与 skills 命令行互通
fangcun sync                  # 按清单与锁物化
fangcun sync --frozen         # CI 用：锁与清单不一致就失败
fangcun update [资产]          # 检查并升级。--dry-run 只看差异，--projects 指定项目
fangcun rollback <快照>        # 回滚到某个快照
fangcun log                   # 查看活动记录
fangcun why <资产>             # 解释它为何生效、来自哪一层。--global 看全局层
fangcun secret set <名称>      # 存入或替换钥匙串里的密钥，终端里输入不回显。rm 删除，ls 列出谁在用
fangcun --read-only <命令>     # 只读模式：拒绝一切写入（7.5）
fangcun --yes <命令>           # 不问，直接应用变更计划
```

会写入的命令先打印变更计划（`+` `~` `−` 每一行），再问「应用？[y/N]」。加 `--yes` 不问直接应用。不在终端里运行（被脚本、Agent 调用）又没加 `--yes` 时，只打印计划，不写。

活动页的检查器会给每条记录附上对应的命令，界面能做的事命令行都能做。

### MVP 明确不做

- 不管理会话状态类资产，例如记忆、任务进度文档。它们是「演化中的状态」而非「配置」，机制不同。
- 不做自建市场，不做账号体系，不做云同步。
- 不代理或拦截 Agent 运行，不做 MCP 网关。
- 不安装 CLI 依赖。只在后续版本做「依赖是否就绪」的检查。
- 不做 skill 质量评测。

### 6.1 形态

- **主窗口**：左边是贯通到顶的侧栏，右边上方是统一工具栏，下面是列表与检查器两栏。没有单独的窗口条。
- **菜单栏常驻图标**：有漂移或可更新时图标右上角亮一个小圆点，展开的菜单里写待处理数，与活动页的待处理数一致，可快速跳到项目。图标的画法见 6.10。
- **命令面板** `⌘K`：搜索资产、项目、动作。`↑↓` 选择、`↩` 打开、`Esc` 关闭，底部一行写这三个键。没有匹配时写「没有匹配的资产或动作」。
- **设置**：应用菜单的「设置…」或 `⌘,` 打开，显示在主窗口里，不另开窗口。侧栏照常显示，右边是设置目录与内容。工具栏写「设置」，副标题「`⌘,` · 改完立即生效」。先只有「通用」一页，分三组：
  - 「写入」：只读模式开关（7.5），说明「拒绝一切写入，只体检和查看」。打开后组内写「只读中 ·『同步』『应用』变灰」。
  - 「快照」：保留天数、每个项目至少保留几个（6.7），都是「− N +」步进器。
  - 「隐私」：「本地优先 · 零遥测」和一句「不需要账号，不上报使用数据」，其余说明进 ⓘ。
  - 最下面一行 `~/.fangcun/settings.toml · 可手改` 和「在访达显示」。目录上方不放搜索框，设置多了再加。
- **命令行** `fangcun`：见上节。

**窗口骨架**，所有页面共用：

- **侧栏**：贯通到窗口顶部，窗口按钮在侧栏顶部。没有「方寸」字标。
  - 五个导航项：**项目**、**资产库**、**套装**、**全局**、**活动**。前四项旁的灰色数字是数量，「活动」旁是待处理数的徽标（浅橙底深橙字）。
  - 项目分组：M0 没有登记，列的是近 30 天会话记录里出现过的工作目录，往上归到 git 根目录（主目录本身、临时目录、主目录下的点目录不算）。M1 起分两组：「已登记」和「近 30 天 · 未登记」，后者只列还没登记的目录，选中后项目卡片里有「登记」。每个项目右边是状态短标签，例如「漂移」「可更新」。未登记的目录照常只读显示生效上下文，和 M0 一样：工具栏标「未登记」，不出「同步」。两组下面是「添加项目…」，选一个目录登记（F3）。
  - 底部固定一块：带文字的「设置 `⌘,`」和「重新体检」，下面一行小字「本地优先 · 零遥测」。
  - 折叠：工具栏的侧栏开关把侧栏整个藏起（macOS 原生做法），不留图标栏。
- **统一工具栏**：在侧栏右边，左起是侧栏开关、后退与前进（侧栏收起时窗口按钮也在这里），然后是页面标题加一行副标题，右边是这一页的控件和主按钮。标题与副标题各页不同，见各小节。
- **列表与检查器**：选中列表中的一行，右侧检查器显示详情。检查器右上角的 × 只关面板，关闭后列表占满宽度；再点任意一行即重新打开。回到上一级用检查器左上的「‹ 名称」，例如从一项回到项目卡片的「‹ evals_studio」。
- **分栏独立滚动**：窗口固定为一屏高，侧栏、列表、检查器各自滚动，滚动一栏时其他栏不动。筛选条、分段控件放在它所筛的列表最上方并吸顶。
- **窄窗口**：窄于 960px 时侧栏收起，工具栏左侧保留窗口按钮和侧栏开关；点开的侧栏浮在内容上，点外面或 `Esc` 收起。窄于 900px 时列表与检查器上下堆叠，整页滚动。
- **浮层**：浮在窗口之上的一律是四角圆角的卡片，不做顶边贴平的 sheet。
  - 面板（变更计划、登记、瘦身计划、套装计划）、命令面板、瘦身托盘：圆角 14。面板在工具栏下方 12px 处居中，遮罩盖住整个窗口。
  - 菜单（例如目标工具）、ⓘ 气泡：圆角 10，菜单离按钮 4px。
  - 提示条：全圆，在窗口底部中间。写入后出现，只写结果和快照号，例如「已回流到来源 · 已留快照」，带「撤销」。
- **ⓘ 说明钮**：说明性文字折进 ⓘ。点击或空格、回车弹出锚定在旁边的气泡（最宽约 280px），再点一次、点别处或 `Esc` 关；悬停也显示；同一时刻只开一个。
- **键盘**：`⌘K` 打开命令面板；变更计划 `⌘↩` 应用、`Esc` 取消；选中某项时 `Esc` 回到项目卡片。弹层打开后焦点进弹层，关闭后回到触发它的按钮。系统开了「减少动态效果」时动效全部关掉（6.10）。

**检查器统一结构**：项目页、资产库、体检报告、全局、活动五处的详情面板用同一套结构，自上而下是：

1. 类型小标签（类型 · 作用层，例如「Skill · 项目」）、名称、状态徽标与版本。
2. 一句白话的「为什么是这个状态」，下面是命令行的对应写法，例如 `$ fangcun why <资产>`。
3. **决定卡片**：只在要人决定时出现，见下面。
4. 字段表。
5. 若干分区，可折叠。分区标题统一用 11px 灰色小字，内容超出时出现细滚动条。

**决定卡片**：要人决定的事都用它，在检查器里排在「为什么」之后、字段表之前。依次是：

1. 状态一句话，例如「副本被改过」。
2. 量化，例如「+3 −1」「每个项目 −6.4k」。
3. 证据：差异、脚本内容，长的可展开。
4. 选项：推荐项排第一、默认选中。
5. 「会写入 · N 处」：随所选选项变，逐条列出文件和改法，写法与变更计划相同（6.8）。多处、跨项目的写入改进变更计划面板。
6. 留哪个快照、能不能撤销，例如「快照 #128 · 可撤销」。
7. 按钮写动作，例如「回流到来源」「回滚」，不写「预览并应用」。

点了按钮就写入，完成后卡片原地显示结果和「撤销」，提示条也给「撤销」。

### 6.2 首次启动：体检报告

- **结论在前**：一行状态「只读扫描完成 · 没有改动任何文件」，一句结论「发现 N 件事，M 件可以一键处理」，下面是三个数字（工具数、项目目录数、资产数）和「先预览 · 写前留快照」加 ⓘ。
- **处理进度**：「N / 5 已处理」加分段进度条，每处理一项点亮一段。
- **四张量化卡片**：每张一个大数字加一句短说明，对应一类发现的影响，例如「每个项目 −6.4k · 每个项目都在缴」「5 份 → 1 份 · 重复副本」「Codex 缺 28 · 分发不齐」「129 天 · 全局锁没跟上目录」。点卡片选中对应的发现。卡片和下面列表前四条说的是同一批发现，是否保留卡片见 BACKLOG D-35。
- **发现列表**：标题「发现 · 按影响排序」，每行是类别（圆点加短标签）、标题、量化、状态。列表末尾一行小字「记录在『活动』· 可回滚」。
- **检查器**：每条发现一张决定卡片，「会写入 · N 处」随发现列出；只读的写「只读扫描，不写任何文件」，「标记已知」写「不写文件，只在体检里记一笔」。分区「命令行同款」给出对应命令。
- 处理完的发现划线并标「已处理」，检查器显示「已处理 · 已留快照」和撤销，1.5 秒后自动跳到下一条。全部处理完时写「5 件都处理完了。下一步：进入项目看看生效上下文。」
- 第一屏就给出价值，不要求先建库、先配置。

- 要处理的状态（漂移、可更新、脚本变更、来源未知）文字加粗。排进计划还没同步的行写「待同步 ↑ b7e9f0」「停用（待同步）」「恢复（待同步）」，常驻不提前扣，旁边写「同步后约 N」。
- 筛选「待处理」后没有结果时写「没有待处理的项」和「漂移、可更新、脚本变更都处理完了」。

**检查器**：按 6.1 的统一结构。决定卡片按状态出现：

- **漂移**：「副本被改过 +3 −1」，差异片段（文件与行号）。处理方式三选一：回流到来源（推荐，默认选中）；丢弃修改（被丢弃的修改另存一份，可找回）；分叉为项目专属（改成本项目自己的文件，提交进仓库，不再跟随来源）。「会写入 · N 处」随选项变。按钮随选项写「回流到来源」「丢弃修改」「分叉到项目」。完成后原地显示结果，例如「已回流到来源」「已丢弃修改」「已分叉为项目专属」（说明「改成本项目自己的文件，提交进仓库。清单和锁里去掉了这一项，方寸不再管它。」），回流时列出同样用这项资产的其他项目（agent-lab、fangcun 等），带「撤销」。
- **可更新**：「有新版本 a1b2c3 → b7e9f0」，逐条列变更，脚本变更标红并写「会执行命令」，可展开看新脚本的前几行和「完整差异：`fangcun update tdd --dry-run`」。「同版本项目一起升级」是复选列表，本项目固定勾选。按钮加入同步计划，之后写「已加入计划」和「撤回」。脚本变更要先展开看过脚本，按钮才可点。
- **全局税**：「全局税：每个项目都在缴」，「16 个飞书 skill 常驻上下文，本项目从未触发」，量化「−6.4k 停用后」。按钮「在本项目停用」和「改为套装…」。停用先加入同步计划，卡片写「已加入计划 · −6.4k」和「撤回」。清单里已经停用的，写「已在本项目停用」和「写在清单 [disable]，其他项目照常加载」，给「在本项目恢复」，同样先加入同步计划。
- **被覆盖**：「被全局同名项挡住」，量化写哪一份不加载，例如「同名时全局优先，v1.3.0 不加载」，ⓘ 写「同步不会自动移走全局那一份：其他项目也在读它」。按钮「查看覆盖项」；工具规则是上层优先、被遮蔽的是项目层这一份时（例如 Claude Code 的 skill），另给「转成套装…」「从全局移除…」，处理全局那一份。
- **来源未知**：「查不到来源」，「哈希不匹配任何来源」，ⓘ 写发现位置和「收编后才能追踪版本与更新」。按钮「去收编」，到资产库。

决定卡片之后是字段表和分区，分区可折叠：

1. **在哪一层声明 · 谁覆盖谁**：全局、套装、项目、个人四行，用层级刻度画。生效的那层标出，被遮蔽的划线，停用的用橙色。工具规则与「下层覆盖上层」相反时，下面一行小字：「这个工具同名时上层优先，与『下层覆盖上层』相反」。
2. **上下文占用**：占本项目常驻的百分比，超过 30% 显示为橙色。
3. **写入了哪些文件**：实际物化的路径与软链指向，以及按键合并的配置项。
4. **最近活动**：这一项的时间线。

**项目卡片**：打开项目、没选中任何一项时，检查器显示项目卡片，已登记和未登记都一样。依次是类型小标签「项目」、名称、状态徽标、一句说明、分区、字段表：

- 已登记：状态徽标按待处理项数写「N 处漂移」「N 处可更新」，都没有时「已登记」。分区「待处理 N」逐行列出已漂移、可更新、脚本变更的项，点一行就选中那一项；没有时写「没有待处理的项」。有排进计划的变更时，下面一块「待同步 N 处变更」按原因列出各几处，写「未写入磁盘」和「预览」。字段表是路径、清单（`fangcun.toml` · `fangcun.lock`）、物化方式、目标工具、提交者、常驻（估算）/ 项目预算。
- 未登记：「未登记」徽标。一块「登记后才能管理」：「从现状生成 fangcun.toml 与 .lock」，ⓘ 写「从目录现状反推清单。查不出来源的项不进清单，留在原处照常生效」和命令行 `fangcun init --from-existing`，按钮「登记…」。字段表是路径、清单、提交者、常驻。

选中某一项后检查器显示那一项。点左上「‹ 项目名」、点列表空白处、按 `Esc`、再点一次侧栏里同一个项目，回到项目卡片。

**同步按钮**：「同步」只在有排进来、还没写到磁盘的变更时是主按钮，写「同步 · N」；没有时是次要样式，不带数字。点了打开变更计划（6.8）。

**登记**：「登记…」打开登记面板，标题「登记 <项目名>」，副标题「先选物化方式」并按提交者人数给建议，例如「提交者 1 位，建议『链接』」。物化方式是单选，建议项标「推荐」。下面「会写入」逐条列文件，最后一句「不会触碰其他任何文件」，按钮「取消」「登记」。登记后卡片写「已登记 · 快照 #N」和「撤销」。

**清单页签**：顶部一句话说明清单的用途，下面三张文件卡可切换：

| 文件 | 角色 | 提交 |
|---|---|---|
| `fangcun.toml` | 项目清单 | 提交到 git |
| `fangcun.lock` | 版本锁，自动生成 | 提交 |
| `fangcun.local.toml` | 个人覆盖 | 不提交 |

默认是「结构化」视图，按区块用表格展示：项目设置，Skills（来源与版本策略，标注哪项来自套装），MCP 服务（启动命令与密钥位置），指令文件（正本与镜像）。可以切换到「源文件」视图，带行号，长行自动折行。界面上的改动会同步出现在两种视图里。

**历史页签**：快照列表，每条写编号、标题、时间与摘要，当前磁盘状态有标记。每条有「回滚到此…」，点了在这一条下面展开「回滚到 #N：会写入 N 处」，逐条列出文件和改法，一句「回滚本身也留快照 #M，可以再撤销」，按钮「取消」「回滚」。

### 6.4 资产库

**工具栏**：标题「资产库」，副标题「每项资产本机只有一份正本 · 多版本并存」。右边是「筛选资产 `⌘F`」和「添加来源…」。

**概要**：列表上方四个数字，每个一句短说明：资产（「Skill 31 · MCP 4 · 指令 3」）、来源（「2 个 git 仓库、2 个本地、npm」）、多版本并存（「各项目固定自己要的那版」）、要处理（「漂移 1 · 可更新 1 · 来源未知 1」）。

**筛选**：类型分段（全部、Skill、MCP、指令）加一个「来源」下拉框，两者可以叠加，吸顶。下拉框默认「全部来源（N）」，按本地开发、GitHub、npm、待收编分组，每项带资产数量；来源再多也只占一个控件。筛选结果为空时提供「清除筛选」。

**列表**：四列：名称 · 来源、谁在用、版本、状态。

- 名称下面一行小字是来源。
- **谁在用**：一条比例条加「N/6」（固定了这项资产的项目 / 已登记的项目），表头带 ⓘ。点比例条在行下方展开一排项目名标签，左边和名称对齐，列不挪位；多版本并存时标签带版本号，漂移的标橙；后面一行「没用到：…」。再点收起。展开和选中无关，换选中行、换筛选时保持，可以同时展开多行。
- **版本**：只有一个版本时写版本号；多个时写「N 个版本 · M 个在用」。
- **状态**：圆点加短标签，例如「1 处漂移」「可更新」「来源未知」「已同步」。

**检查器**：按 6.1 的统一结构，类型小标签写「类型 · 资产库」。

- **决定卡片**：来源未知的资产给「收编进资产库」：「记为本地来源，原位换成链接 · 6 个项目照常加载」，「事前备份 · 可撤销」，按钮「收编」。完成后写「已收编为本地来源，原位置替换为受管链接，事前已备份」，提示条「已收编 pr-review · 原位置换成受管链接 · 已留快照」带撤销。
- **版本 · 谁固定在哪一版**：版本轨道是这一页的主角。每个版本一个节点，按时间排开，标「锁定中」「最新」「分叉」「旧版」「未收编」，节点下列出固定在这一版的项目；没有项目固定的写「没有项目固定在这一版」。漂移的项目标「漂移」。
- **详情**：字段表，来源、正本、常驻（tokens，估算）、含脚本。含脚本时标红。
- **最近活动**。

### 6.5 套装

**套装**是一组常一起用的资产，起个名字给多个项目复用，例如「工程基线」「飞书办公」。它介于全局和项目之间：比装进全局更精准，不会给无关项目增加上下文负担；比逐个项目添加更省事。

**工具栏**：标题「套装」，副标题「一组资产，项目按需启用」，右边「新建套装」。

- **左栏**：「全部套装 · N」加 ⓘ（「套装是一组资产，项目在清单里写 `bundles = [...]` 启用。改套装，所有启用它的项目一起跟着变」），下面是套装列表。每个条目是名称与常驻估算、「N 项资产 · N 个项目」，和一条按资产常驻画的细条。左栏可以折叠为首字方块组成的窄条，折叠后仍可切换和新建。
- **右侧详情**：
  - 名称、一句说明、「每个启用的项目常驻 N」。
  - **组成地图**：和项目页的上下文地图同一画法，每项资产按常驻占宽度，颜色表示类型；小于 12% 的块不写字，悬停看名称和常驻。
  - 清单写法 `fangcun.toml · bundles = ["<名称>"]`。套装文件的写法见 7.4。
  - **包含的资产**：类型、名称、版本策略（如「跟随 main」「固定 v1.3.0」）、物化方式与状态（如「链接 · 1 处漂移」）、常驻。
  - **哪些项目启用它**：每个项目一个开关，旁边写「先出计划 · 各留快照」。开关变化时标出「将启用」「将停用」，底部一行汇总「N 处变更 · 涉及 N 个项目」，按钮「还原」「预览变更」。
- **套装计划**：「预览变更」打开面板，标题「套装『<名称>』· N 处变更」，副标题「改各项目的 fangcun.toml 再同步 · 各留快照」。逐条列出每个项目的变更，例如「bundles 加入『工程基线』」「链接 3 项 · 常驻 +N」「bundles 去掉『工程基线』」「移除链接 · 常驻 −N」。最后一句「不碰其他文件」，按钮「取消」「应用」。应用后提示条「套装『<名称>』已同步到 N 个项目 · 每个项目各留快照」，带撤销。

              ┌ 已选 3 项 · 转套装 1 · 移除 2 · 每个项目最多 −7.0k  [清空] [预览计划] ┐
```

**工具栏**：标题「全局」，副标题「每个项目都会加载这一层，越薄越好」，右边是目标工具（6.3 同一控件）。切换后地图与列表只算该工具实际加载的内容。

**概要与地图**：列表上方一块，标题「全局层 · 每个项目都在缴 · 估算」。

- 左边是「11.8k / 项目预算 20k · 占 59%」，右边是「照建议瘦身后 N · 每个项目省 N」。
- 下面是和项目页同一画法的地图：每一项按常驻占宽度，全局项都画斜纹，剩下的部分虚线画出，写「留给项目自己的 N」。
- 瘦身之后，数字跟着变。

**筛选与快速勾选**：吸顶的一行。

- 类型分段：全部、Skill、MCP、指令，每个带当前工具下的数量。
- 「勾选」后面两个短按钮，带对应状态的圆点：「从未使用 N」和「少数在用 N」，全文进 title。点一下就勾选对应的行，不改变筛选。
  - 「从未使用」勾选近 30 天没有项目用到的行，以及「被覆盖」「同名冲突」的行。
  - 「少数在用」勾选只有 1–2 个项目用到的行（建议转套装）。

**列表**：

- 不分组，按常驻估算从高到低排列。全局的每一项对每个项目成本相同，所以这个顺序就是瘦身收益的顺序。
- 行首是复选框，表头的复选框全选当前列表。
- 四列：名称与位置、谁在用、建议、常驻。类型用名称前的图标表示。
- 名称下面一行小字是位置，用等宽字体，例如 `~/.agents/skills/lark-*` 或 `~/.claude.json · mcpServers.context7`。
- 来源相同的一组资产合并成一行，名称后带数量标记，例如「lark-* 飞书 skill · 16 项」。
- **谁在用**：一条连续的比例条加「1/6」，不画「项目 × 资产」矩阵，项目变成几十个也不变宽。表头的 ⓘ 写统计口径：近 30 天在本机会话里触发过它的项目 / 已登记的项目，只在本机统计，不上传；指令文件每次会话都全文加载，没有触发可数。指令文件这一列写「全文加载」，不画条。
- 点比例条在行下方展开一排项目名标签，左边和名称对齐，列不挪位；同名冲突的标橙，0/6 写「近 30 天 6 个项目都没用到」，全文加载的写「每次会话都读全文：」加 6 个项目。展开与选中、勾选无关，换选中行、换筛选时保持，可以同时展开多行。
- 被项目层覆盖的行，名称划线。
- 列表末尾有一行小字，说明别的工具还加载了什么，例如「另有 2 项只被 Codex 加载」，点了切换工具。
- 筛选结果为空时显示「这一类在当前工具的全局层里没有资产」和「清除筛选」。

**建议**：按「近 30 天有多少项目用到」给出，直接对应建议的动作，在列表「建议」一列用圆点加短标签显示。

| 标签 | 颜色 | 含义 | 建议的动作 |
|---|---|---|---|
| 建议转套装 | 蓝 | 只有一两个项目用到 | 转成套装 |
| 从未使用 | 橙 | 近 30 天没有项目触发 | 从全局移除 |
| 被覆盖 N 处 | 灰 | 有项目在项目层放了同名项，按工具规则项目层生效，把它遮蔽了（例如 MCP） | 从全局移除 |
| 同名冲突 N 处 | 灰 | 有项目在项目层放了同名项，但按工具规则全局这一份生效（Claude Code 的 skill），或两份都加载（Codex 的 skill） | 转成套装或从全局移除 |
| 全文加载 | 灰 | 指令文件，每个项目的每次会话都全文加载，没有「触发」可统计 | 只放每个项目都需要的约定 |
| 来源未知 | 紫 | 内容哈希与任何来源都不匹配 | 先去资产库收编 |
| 常用、多数项目在用、每个项目都用 | 绿 | 一半以上的项目用到 | 留在全局 |

**瘦身托盘**：勾选任意一行，或在检查器里点「加入托盘」，窗口底部浮出托盘：「已选 N 项 · 转套装 N · 移除 N · 每个项目最多 −N」，按钮「清空」「预览计划」。

**检查器**：按 6.1 的统一结构。

- 类型小标签写「类型 · 全局层」。下面是名称（成组的带数量）、状态徽标、一句说明。
- **决定卡片**：写建议和数字，例如「只有 client-acme 用到。转成套装、只给 client-acme 启用，其余 5 个项目每个省下 6.4k 常驻」，量化「−6.4k × 5 个项目」。按建议给按钮：
  - 建议转套装：「加入托盘」「转成套装…」。
  - 从未使用、被覆盖：「加入托盘」，ⓘ 写「资产库保留正本，随时可加回」。
  - 来源未知：「去收编」。
  - 建议留在全局的项：写「留在全局 · 不用动」，没有按钮。
- **用到它的项目 · 近 30 天**：只列在用和同名冲突的项目全名；没用到的折成一行「其余 5 个没用到」，点开才列名字。指令文件写「6 个项目每次会话都读全文」。
- **分发到哪些工具**：
  - Skill 列出 Claude Code、Codex、Windsurf 三行，各写目标路径和「已链接」或「没有分发」。
  - MCP 与指令文件列出所在工具的配置路径，标「按键合并」或「全文加载」，其他工具标「未配置」。
- **详情**：字段表：位置、来源、版本、常驻、含脚本。常驻写成「6.4k / 每个项目（估算）」，达到 3k 时显示为橙色；来源未知时来源一栏为紫色；含脚本或带启动命令时标红。
- **最近活动**，最下面附命令行写法 `$ fangcun why <资产> --global`。

**瘦身计划**：托盘的「预览计划」打开面板，标题「瘦身全局 · N 项」，副标题「用到它的项目照常加载 · 应用前各留快照，可撤销」。按每项的建议分组，不改动作含义：

- **转成套装「飞书办公」**：建议转套装的写成套装，用到它的项目在清单里加上套装，照常加载，其余项目不再加载。变更是 `+ ~/.fangcun/bundles/飞书办公.toml`（新套装 · lark-* 16 项）、`~ <项目>/fangcun.toml`（bundles 加上「飞书办公」）、`− 16 个全局链接`。
- **从全局移除 · 仍有项目在用**：标橙，写「这些项目会不再加载它，除非它们的清单里另有声明」，列出在用的项目。
- **从全局移除**：近 30 天没有项目用到的，「资产库保留正本，随时可加回」。被同名项挡住的写明移除后哪些项目改用自己的版本，例如「evals_studio、blog-site 改用项目里的 v1.3.0」。

底部一句给出结果，例如「6 个项目常驻各减 N（估算），用到的项目照常加载它」，按钮「取消」「应用 · N 处变更」。

**转成套装**：检查器里的「转成套装…」直接打开套装面板，版式与变更计划相同。

```

- 标题是「把 N 项转成套装」，副标题写「应用前各留快照，可撤销。资产库里的正本不受影响」，长说明进 ⓘ。
- **套装名称**：可以改。默认名按所选内容给出，例如选中飞书 skill 时是「飞书办公」。旁边显示清单写法 `bundles = ["飞书办公"]`。
- **哪些项目需要它**：六个项目的复选列表，已按「用到」预选。只勾选了一个项目时，多一个选项：不建套装，直接写进那个项目的清单。选了它，计划里就没有新建套装文件那一行。
- 计划里的三类变更：
  - `+` 新建套装文件 `~/.fangcun/bundles/<名称>.toml`。
  - `~` 所勾选项目的 `fangcun.toml`，在 bundles 里加入这个套装。
  - `−` 当前工具全局目录里的链接或配置项，注明「移出全局层，已备份」。

**应用之后**：

- 被处理的行从列表消失，概要和地图跟着变短。侧栏「全局」与「套装」旁的数字同步变化。
- 提示条写明结果并带撤销：
  - 瘦身计划：「已瘦身全局 N 项，每个项目最多 −N · 已留快照」。
  - 转成套装：「已创建套装『飞书办公』，写入 1 个项目清单 · 已留快照」，另有「去套装页」链接。
- 点撤销后提示「已撤销，恢复到上一快照」。

**其他页面上的相关入口**：三个按钮与瘦身有关，做的是同一件事或它的局部版本。

| 入口 | 按钮 | 做的事 |
|---|---|---|
| 体检报告的「全局税」发现 | 创建套装 | 转成套装，在体检里就地完成 |
| 项目页检查器 | 改为套装… | 转成套装，从项目页发起 |
| 项目页检查器 | 在本项目停用 | 不动全局，只在这个项目的清单里写入停用 |

**没有全局清单**：全局层就是各工具的全局目录，首版不为它另设清单文件。值得在新机器上还原的东西，应该进套装或项目清单。

**阶段**：列表、地图、建议都不写文件，随 M0 提供。它们依赖的使用数据也在 M0 读取。转成套装与从全局移除属于 M1。

活动相关的界面有三处，它们是同一份记录的不同切面：

| 位置 | 范围 | 用途 |
|---|---|---|
| 检查器的「最近活动」 | 单个资产 | 看这一项经历过什么 |
| 项目页与全局页的「历史」页签 | 单个项目或全局层 | 在这个范围内回滚 |
| 活动页 | 所有项目与全局层 | 跨项目追溯、回滚，找到待处理的事 |

**工具栏**：标题「活动」、副标题，右边是「项目」下拉框和「检查更新」。

- 下拉框列出「全部项目（N）」、每个已登记项目和「全局层」，选中某一项后控件变为强调色。
- 「检查更新」手动检查所有已声明的上游来源，旁边小字写上次检查的时间，例如「上次 09:12」。启动时也自动查一次（9.3）。查到的新版本进「待处理」。命令行是 `fangcun update --dry-run`。

**筛选**：列表最上方吸顶的一行，切换筛选或项目时它不动，只有下面的结果变。

- 左边一组「全部 | 待处理 N」，竖线后是类型：同步、漂移、升级、收编、回滚、体检、校验、密钥。「待处理」的数字为 0 也占位（变灰）。
- 「升级」同时包含「可更新」的记录。
- 类型与「项目」下拉框可以叠加。
- 最右边是「N 条」计数，定宽。
- 这一行固定一行高，类型按钮放不下时在行内横向滚动，不换行。列表宽度不到 600px 时藏起「N 条」计数和时间线的快照列。
- 筛选结果为空时显示「这个筛选下没有记录」「换个类型或项目看看」和「清除筛选」。

**列表**：

- 五列：时间、类型、事件与项目、快照、状态。
- 每行两行文字。上面是事件标题，下面的小字是「项目 · 触发方」。
- 涉及一两个项目时写出项目名，更多时写成「evals_studio 等 5 个项目」，全局层的记录写「全局层」。
- 按天分组，新的在上。分组标题写成「今天 · 11-13」「昨天 · 11-12」「11-11 周二」。
- 列表末尾一行小字：「更早的记录保留在 `~/.fangcun/journal`，命令行可用 `fangcun log` 查看。」

**待处理**：

- 时间线上方置顶的一组，标题「待处理 · 置顶 N」，带 ⓘ（「要你决定的事置顶在这里，不进下面的时间线；处理后才作为一条记录落进时间线。也显示在菜单栏图标的小圆点上」）。
- 目前有两类：漂移（橙）和可更新（蓝）。每行写量化，例如「+3 −1」，和项目页的数字一致。
- 类型筛选把它们筛掉时，原位留一行「N 条待处理不在『某类』里 · 查看」。选「待处理」只看这一组。
- 没有待处理时写「没有待处理的事」和「漂移、上游更新出现时会置顶在这里」。
- 活动页不处理它们，只负责带你过去。行内和检查器给出跳转：漂移是「去处理」，可更新是「查看差异」，都跳到项目页并选中那一项，在检查器的决定卡片里完成。
- 侧栏「活动」旁的数字是待处理总数，不受筛选影响。分组标题里的 N 是筛选后的数量。

**类型**：

| 类型 | 含义 | 示例 |
|---|---|---|
| 同步 | 按清单与锁物化，包括登记项目 | 同步 3 处变更；登记项目，生成清单与锁 |
| 漂移 | 受管副本被修改 | project-harness 的副本被修改 |
| 升级 | 资产换到新版本 | 升级 frontend-design v1.1.0 → v1.3.0 |
| 可更新 | 来源有新版本，等你确认 | tdd 上游有新提交 b7e9f0 |
| 收编 | 副本归并进资产库 | 收编 project-harness：5 份副本归并为 1 份正本 |
| 回滚 | 撤销某次写入 | 回滚到快照 #88 |
| 体检 | 只读扫描 | 首次体检：扫描 7 个工具、61 个项目目录 |
| 校验 | 在本机运行 `fangcun sync --frozen` 的结果 | 校验失败：锁与清单不一致 |
| 密钥 | 存入、替换、删除钥匙串条目。只记名称和位置，从不记值 | github-token 迁入钥匙串 |

「校验」只记录在本机运行的校验，例如提交前的钩子。远端 CI 的结果没有通道回到本机，留到 V2。

**状态**：

| 状态 | 颜色 | 含义 |
|---|---|---|
| 已应用 | 绿，回滚类记录用灰 | 已写入文件并留了快照 |
| 待处理 | 橙或蓝 | 等你决定，置顶显示 |
| 失败 | 红 | 没有写入，例如校验不通过 |
| 已回滚 | 灰，标题划线 | 这次写入后来被回滚了 |
| 已记录 | 灰 | 监听到的变化，没有写入任何文件 |
| 只读 | 灰 | 体检扫描 |

**触发方**有五种：桌面应用、命令行、文件监听、上游检查、首次启动。从终端运行 `fangcun` 产生的记录同样出现在这里。

**快照**：

- 快照按项目各自编号。示例里 evals_studio 到了 #127，client-acme 是 #41。
- 一次操作涉及多个项目时，活动页只有一条记录，每个项目各留一个快照。列表里显示第一个编号，检查器里写全，例如「#126 · #63」或「#125 等 5 个」。
- 没有写入文件的记录，快照一列显示「—」，检查器里写「无，未写入文件」。
- 快照和它的备份默认保留 30 天，并且每个项目至少保留最近 20 个，可在设置里调整。记录本身一直保留。快照过期后，这条记录的回滚按钮置灰并说明原因。

**检查器**：沿用统一结构。

- 类型小标签写类型和快照，例如「同步 · 快照 #127」。下面是标题、状态徽标、一句说明。
- 操作区（见下表）在说明之后、字段表之前。
- 字段表：项目、时间、触发、快照。
- **写入了哪些文件**：这次实际执行的变更，写法与同步预览一致。没有快照的记录，这一分区的标题改为「涉及的文件」，只读或未改动的文件用 `=` 标记。
- **命令行**：做同一件事的命令和它的输出，例如 `fangcun sync` 与「3 处变更 · 快照 #127」。
- 操作区按记录的情况给出不同内容：

| 记录 | 操作区 |
|---|---|
| 已应用的写入 | 「回滚到这一步之前」决定卡片，见下面「回滚」 |
| 已回滚的写入 | 一句「这次变更已被回滚，磁盘状态与上一快照一致」 |
| 漂移 | 「在项目页处理」，跳到项目页并选中那一项 |
| 可更新 | 「查看差异」，跳到项目页并选中那一项 |
| 校验失败 | 「打开项目」 |
| 体检 | 「打开体检报告」 |
| 全局层的记录 | 「去全局页」 |
| 快照已过期 | 置灰的「回滚」，写「#1 已过期 · 记录仍在」，下面一句原因：「快照 #1 已过期，备份已清理。快照默认保留 30 天，每个项目至少保留最近 20 个，可在设置里调整。记录仍在。」 |
| 密钥 | 一句「密钥记录不能回滚，钥匙串条目保持现状。要撤销，用『替换』或『删除』再记一条。」 |

**回滚**：已应用的写入在检查器里给「回滚到这一步之前」决定卡片，写「反向变更 · 磁盘回到 #126」，逐条列出逆向的变更计划，「回滚后可再撤销」，按钮「回滚」。跨项目或多处的回滚也可以打开同样内容的面板：

```
┌─ 把 evals_studio 回滚到快照 #126 ──────────────────────────────────┐
│  撤销「同步 3 处变更」。只动这次变更写过的文件。                   │
│                                                                    │
│  − .agents/skills/tdd      移除链接                                │
│  − .claude/skills/tdd      移除链接                                │
│  ~ .mcp.json               删除键 mcpServers.github，其余键不动    │
│                                                                    │
│  回滚本身也会留一个快照，可以再撤销。      [取消]  [回滚 ⌘↩]       │
└────────────────────────────────────────────────────────────────────┘
```

- 标题写明范围和目标快照。跨项目的记录写成「把 2 个项目回滚到快照 #125 · #62」。项目的第一条记录没有上一个快照，写成「回滚到登记前」或「回滚到收编前」。
- 下面列出逆向的变更计划。
- 有文件被后来的变更动过时（回滚规则第 6 条）：这些行标橙，说明改成「#126 之后也改过这个文件」；卡片上方一条橙色提示「N 个文件被后来的变更改过。先回滚『…』（快照 #126 · #63），再回滚这一条。不做自动合并」，带「查看那条记录」；「回滚」按钮置灰。先回滚了后面那条，再打开预览时提示消失。
- 应用后发生三件事：
  1. 列表顶部多一条「回滚」记录，带一个新快照。
  2. 原记录的状态变为「已回滚」，标题划线。
  3. 出现提示条「已回滚到 #126 · 磁盘状态逐字节一致」，带「撤销」。点撤销后提示「已撤销回滚」。

**回滚规则**：

1. 回滚执行的是那次变更的逆操作，只动那次变更写过的文件。
2. 回滚本身也留快照，所以可以再撤销。记录只增不删。
3. 跨项目的记录一起回滚。
4. 收编前、覆盖前的原文件都有备份，回滚时从备份还原。丢弃漂移修改也是一条写入记录，想找回被丢弃的修改，对它回滚即可。
5. 资产库里的正本不随回滚删除。例如回滚 skill-b 的升级后，v2.1.0 仍留在资产库。
6. 回滚较早的记录时，如果后来的变更也动过同一批文件，回滚预览里会标出这些文件，并要求先回滚后面的记录。不做自动合并。
7. 没有写入文件的记录不能回滚，包括待处理、失败、已记录、只读。密钥记录也不能回滚，钥匙串条目保持现状。

**没有「更新中心」页面**：可更新的入口就是这里的待处理项，处理在项目页检查器里完成。跨项目的批量升级也在检查器里做，勾选受影响的项目即可。

**阶段**：M0 只写方寸自己的 `~/.fangcun`，体检记录存进 `~/.fangcun/journal`，重启后和 `fangcun log` 都看得到。这里只有体检和「已记录」两类记录。回滚随 M1 开放。

### 6.8 同步：变更计划

```
┌─ 同步 evals_studio · 4 处变更 ──────────────────────────────────────┐
│  应用前留快照 #128 · 可在「历史」回滚                               │
│                                                                      │
│  升级 tdd 到 b7e9f0                                  [移出计划]      │
│   ~ .agents/skills/tdd         链接改指 tdd@b7e9f0，含新脚本 run-tests.sh │
│   ~ fangcun.lock               tdd 记下 b7e9f0 的内容哈希             │
│  在本项目停用 lark-* 16 项                            [移出计划]      │
│   ~ fangcun.toml               [disable] 加上 lark-*（只影响本项目）  │
│   ~ .claude/settings.json      skillOverrides 16 个设为 off，其余键不动│
│                                                                      │
│  不碰其他文件                                [取消]   [应用 ⌘↩]      │
└──────────────────────────────────────────────────────────────────────┘
```

- 计划只装排进来、还没写到磁盘的变更。检查器里的停用、恢复、升级等操作先加入同步计划，由工具栏的「同步 · N」统一预览和应用。
- 标题「同步 <项目> · N 处变更」，副标题「应用前留快照 #N · 可在『历史』回滚」。
- 变更按原因分组，组标题写原因，例如「升级 tdd 到 b7e9f0」「在本项目停用 lark-* 16 项」，每组可「移出计划」。每行是 `+` / `~` / `−`、路径、改法。
- 没有排进来的变更时，副标题写「没有排进来的变更」，正文写「磁盘已经和清单一致，没有要写的」。
- 底部一句「不碰其他文件」，按钮「取消」「应用 `⌘↩`」。应用后出现提示条，并生成一个快照。

全局页的瘦身计划、转成套装，套装页的套装计划，登记面板，都是同一种变更计划，见 6.3、6.5、6.6。变更涉及多个项目时，应用后每个受影响的范围各留一个快照，在活动页是同一条记录。

### 6.9 关键流程

1. **给项目加资产**：`⌘K` 搜索，回车加入，弹出变更计划，应用。全程不离开键盘。
2. **处理漂移**：点上下文地图里带圆点的块，或侧栏、活动页的「去处理」，检查器定位到该资产，在决定卡片里看差异，三选一，看「会写入 · N 处」，点按钮。选「回流」时列出同样使用该资产的其他项目，逐个决定是否跟进。
3. **升级**：从活动页的待处理项点「查看差异」，或直接在项目页选中这一项，在决定卡片里看差异。脚本改动标红，审阅后加入同步计划，再「同步」应用。不满意就在「历史」或「活动」里回滚。
4. **全局瘦身**：「全局」页按常驻成本从高到低排列，并标出近 30 天有几个项目用到。点「少数在用」「从未使用」勾选一批，进托盘，「预览计划」按建议分组确认，应用。之后可以在套装页继续调整。
5. **追溯与回滚**：发现 Agent 行为变了，打开活动页，用「项目」下拉框筛到这个项目，找到可疑的那条记录，看它写入了哪些文件，在「回滚到这一步之前」卡片里点「回滚」。

### 6.10 视觉与交互基调

视觉规范见设计系统「方寸 2」（在「墨格」上改出来，画布的 v2 设计系统画板），要点如下。

- **原生 macOS 质感**：贯通到顶的侧栏、统一工具栏、系统字体（SF Pro + 苹方，等宽 SF Mono）、深浅色成对定义并跟随系统。真实应用里侧栏用系统的半透明材质。非 Mac 环境回落到 Inter、Noto Sans SC、JetBrains Mono。
- **冷中性表面**（2026-11-21 人定）：石板色相的填充与发丝线，浅色侧栏 `#F5F6F8`、检查器 `#FBFBFC`、凹面 `#F6F7F9`，深色窗口 `#17181B`、侧栏 `#1D1E22`。卡片、标签、搜索框、分段控件不垫灰，用白底加 0.5px 发丝环。
- **材质分层**：从后到前是侧栏、工具栏、检查器、决定卡片、浮层。层次靠底色和 0.5px 发丝线分，不靠阴影；阴影只给浮在窗口之上的东西（面板、菜单、ⓘ 气泡、托盘、提示条）。
- **四级文字**：正文、次要、说明、装饰。说明级文字在窗口、侧栏、强调浅底上对比度不低于 4.5:1。
- **密而不乱**：正文 13px，间距以 4px 为单位递增。
- **一个强调色**：黛蓝（浅色模式 `#3552D4`，深色模式 `#7D93FF`），只用在可操作的元素和当前选中的状态上。侧栏选中用强调浅底。
- **六种状态语义**：已同步、漂移、可更新、脚本变更、来源未知、被覆盖。状态一律用「圆点加短标签」表达，不只靠颜色。列表里不加底色；要处理的（漂移、可更新、脚本变更、来源未知）文字加粗；徽标、提醒条才用浅底。漂移用橙色，可更新用蓝色，避开红绿对立。
- **签名元素**：
  - **上下文地图**：每一项按常驻占面积，总宽度是预算；颜色表示类型，斜纹表示来自全局，圆点表示待处理，虚线是剩余（6.3）。
  - **层级刻度**：四格自左向右是全局、套装、项目、个人，所在层那一格加高、用强调色。列表里 3.5px 宽、11/7px 高，检查器的层叠图同一画法。
  - **决定卡片**：见 6.1。
- **按钮六种**：主（一屏一个，白字，深色下深字）、次（白底加发丝环）、轻（目标工具也用它）、危险（红字白底，悬停才出浅红底）、禁用、图标（28px 方；ⓘ 说明钮 18px）。高 28、小号 24，圆角 7 / 6，字重 500。文字 2–6 个字、动词开头，长对象名（套装名、路径）放进 title。光标一律是箭头，按下缩到 0.97。
- **分段控件**：没有灰轨道，选中段白底加发丝环，其余只有文字。
- **圆角**：面板、命令面板、托盘 14；菜单、ⓘ 气泡 10；按钮 7 / 6；提示条全圆。
- **动效只交代因果**：入场一律 ease-out（`cubic-bezier(.2, .8, .2, 1)`），没有回弹；可反复切换的（折叠、弹层）用 transition，中途能打断。高频操作（菜单、命令面板、选中）不加动效。浮层在工具栏下方浮出，自上 6px 滑入。系统开了「减少动态效果」时全部关掉。
- **图标**：16px 网格、1.3–1.5px 描边、圆角端点，和 SF Symbols 的粗细对齐；真实应用里能用 SF Symbols 的就用。图标不单独表达状态。能用图标加 2–4 字短标签说清的，不写段落，说明、注释、图例折进 ⓘ。
- **目标工具图标**（2026-11-21 人定「先用近官方版，发布前查」）：贴近各家公开使用的标志，简化成 16px 可读的线条。Claude Code 是陶土橙的星芒（`--tool-cc: #D97757`，浅深同值）；Codex 是 OpenAI 六瓣结，单色跟随文字色。只用来指明目标是哪个工具，不当作方寸自己的标识。正式发布前确认各家商标使用规定（R-07），不允许就换回自画图标。
- **应用图标**：
  - 图形是「方中之方」：圆角描边的外方里套一个实心内方，和菜单栏图标是同一个形。线宽、内外方比例、圆角按图标网格精修。
  - 黛蓝底（`#3552D4`）、白色图形，用 macOS 标准的圆角方形底板与网格。
  - 用 Icon Composer 出分层的 `.icon` 文件，浅色、深色、着色、透明四种外观交给系统生成；不支持的旧系统回落到 `.icns`。Tauri 打包还不认 `.icon`，在那之前只出 `.icns`，`.icon` 等 Tauri 支持再做（9.3）。
  - 菜单栏图标是单色模板图：「方中之方」的描边版，系统自动适配深浅色。有待处理时右上角加一个小圆点，不放数字。
- **文件即真相**：路径、哈希、清单片段一律用等宽字体原样展示。
- **交互规则**（设计系统第 10 节）：
  - 写入前先列清单：会落盘的按钮，点之前就能看到「会写入 · N 处」。完成后原地显示结果和撤销，提示条也给撤销。
  - 计划只装排进来的变更；没写到磁盘的改动不提前算进常驻，只写「同步后约 N」。
  - 批量操作不改动作含义：瘦身按每项的建议分组。
  - × 只关面板，回到上一级用「‹ 名称」。
  - 筛选条不动：放在所筛列表的最上方并吸顶，上方不放会随筛选出现或消失的内容；计数为 0 也占位。
  - 待处理置顶：要人决定的事置顶在列表顶部的一组，不进时间线。
  - 状态只有一个来源：处理完一项，列表、检查器、层级、地图、侧栏、活动徽标同时变；同一件事在各页的数字一致。
  - 入口带文字：图标只作补充。
  - 不只靠颜色：每个状态有圆点加文字，地图的块有可读名称。
  - 键盘与焦点见 6.1。
- **空状态即引导**：说清楚为什么空、下一步做什么；没有资产时直接给体检入口。
- **错误**：写清楚哪一步失败、磁盘现在是什么状态，例如「写入 .mcp.json 失败：文件被其他程序锁住。已按快照 #128 还原，磁盘没有变化」，带「重试」。只读模式下显示提示「只读模式 · 不写入任何文件」。

## 7. 技术架构

### 7.1 选型建议

**Rust 内核 + Tauri 2 外壳 + React 界面。**

- 内核是独立的 Rust 库，桌面应用与命令行共用。这保证 CI 与界面的行为完全一致。
- Tauri 包体小，访问文件系统与钥匙串方便，将来上 Windows 与 Linux 不必重写界面。
- 备选是 SwiftUI 界面加 Rust 内核，Mac 质感最好，但跨平台时界面要重做。你明确提到未来全平台，所以不推荐。

### 7.2 模块

```
┌──────────────── 桌面应用 (Tauri + React) ────────────────┐
│   项目 · 资产库 · 套装 · 全局 · 活动 · 体检 · 菜单栏 · ⌘K  │
└───────────────────────────┬──────────────────────────────┘
                            │              ┌── 命令行 fangcun
┌───────────────────────────▼──────────────▼───────────────┐
│                        内核 (Rust)                        │
│  扫描器 │ 资产库 │ 解析器 │ 物化器 │ 监听器 │ 估算器       │
│  ─────────────────────────────────────────────────────── │
│  适配器层：每个 Agent 工具一份声明式描述                    │
└──────────────────────────────────────────────────────────┘
        │                │                    │
   ~/.fangcun/      项目目录              macOS 钥匙串
   (正本与索引)   (清单、锁、物化产物)
```

- **扫描器**：遍历并归并，产出资产清点与体检发现。同时只读本机各工具的会话记录，统计每项资产近 30 天在哪些项目被触发。这些数据不上传。
- **资产库**：内容寻址存储，git 来源走本地裸仓库缓存，索引用 SQLite（`~/.fangcun/index.sqlite`）。
- **解析器**：合并四层作用域，解出确定结果，写锁。
- **物化器**：计划、应用、快照、回滚。记录所有权。共享的 JSON 与 TOML 按键合并。每次写入记一条到 `~/.fangcun/journal`，活动页读的就是它。
- **监听器**：基于 FSEvents 监听已登记项目与全局目录，发现漂移。
- **估算器**：本地估算 token，明确标注为估算。

### 7.3 适配器是数据，不是代码

各工具的目录约定每月都在变，这是最大的工程风险。适配器因此设计为声明式描述，可独立于应用版本热更新。每份适配器声明：

- 各作用域下 skill、MCP、指令文件的读取位置
- 会话记录的位置与格式，用来统计触发次数
- 同名时的优先级规则
- MCP 配置的文件格式与字段映射
- 能力标记：是否跟随软链、是否支持项目级 MCP、是否支持按项目停用

工具不支持某项能力时，界面明确告知，不静默失败。每个适配器配一套回归样例，工具升级后自动验证。具体路径需在实现时对照各工具当期文档逐一核实，本文不写死。

### 7.4 清单示例

```toml
# fangcun.toml —— 提交到 git
[project]
targets = ["claude-code", "codex"]
mode    = "link"                 # link 或 vendor
budget  = 20000                  # 常驻预算（估算值），不写时 20000

bundles = ["工程基线"]

[skills]
tdd             = { source = "github:obra/superpowers", track = "main" }
skill-b         = { source = "github:acme/skills", pin = "v2.1.0" }
project-harness = { source = "local:luyao-skills", pin = "4d9b1eb" }

[mcp.github]
command = "npx"
args    = ["-y", "@modelcontextprotocol/server-github"]
env     = { GITHUB_TOKEN = "secret:github-token" }   # 值在钥匙串

[instructions]
canonical = "AGENTS.md"          # 正本
mirror    = ["CLAUDE.md"]        # 生成为对正本的引用
```

锁 `fangcun.lock` 由方寸生成，和清单一起提交到 git，不手改。格式也是 TOML，一项资产一节：

```toml
# fangcun.lock —— 方寸生成，提交到 git，不要手改
version = 1

[skills.tdd]
source = "github:obra/superpowers"
track  = "main"                  # 照抄清单里的约束，换了约束就重新解析
commit = "b7e9f0c2…"             # 解析出的确切提交
path   = "skills/tdd"            # skill 在仓库里的目录，按名字找到的（F2）
hash   = "9f2c…"                 # 内容哈希，算法见下
bundle = "工程基线"              # 来自套装时写套装名

[skills.skill-b]
source = "github:acme/skills"
pin    = "v2.1.0"
tag    = "v2.1.0"
commit = "41ad0e27…"
hash   = "0d81…"

[mcp.github]
hash = "77c3…"                   # 启动命令、参数、环境变量（密钥只记引用）的哈希

[instructions."AGENTS.md"]
path = "AGENTS.md"
hash = "a9e4…"
```

- **三类都记**：Skill 记来源、跟随方式、确切提交、标签（有就记）、内容哈希；MCP 记启动配置的哈希，升级差异里启动命令的变化据此单独高亮（7.5）；指令文件记正本的内容哈希。来自套装的项写 `bundle`。
- **内容哈希**与 `skills-lock.json` 用同一种算法，导入导出时直接对得上：取目录下全部文件（跳过 `.git`、`__pycache__`、`__pypackages__` 目录和 `metadata.json`），相对路径用 `/` 连接、按 UTF-8 字节排序，依次喂入「路径、`\0`、内容长度（十进制）、`\0`、内容」，SHA-256，十六进制。不含 NUL 字节的文件把 CRLF 先换成 LF，长度按换过的算；含 NUL 的看作二进制，原样喂入。其余文件都算，包括 `.DS_Store`、`node_modules`。软链只跟随到目录以内，指向目录外的跳过。导入旧版（v1）`skills-lock.json` 时，先按它的旧算法校验，再换算成这一种。
- **不进锁的**：物化出了哪些文件、用链接还是入库，因机器而异，记在本机 `~/.fangcun/state/` 里，每个项目一份。同步、卸载、漂移检测都读它。

**按项目停用**写在清单的 `[disable]` 一节，按类型列名字，`*` 通配：

```toml
[disable]
skills = ["lark-*"]              # 停用全局的 16 个飞书 skill，只影响本项目
mcp    = ["playwright"]
```

同步时写进各工具自己的开关：Claude Code 是项目 `.claude/settings.json` 的 `skillOverrides` 设 `"off"`，Codex 是 `.codex/config.toml` 的 `[[skills.config]] enabled = false`。MCP：Codex 是 `.codex/config.toml` 里那一项的 `enabled = false`；Claude Code 没有能提交的按项目开关，写本机 `~/.claude.json` 里这个项目那一节的 `disabledMcpServers`（和 `/mcp` 的开关同一处），清单照样提交，每台机器同步时各自写。通配在同步时按工具实际读到的名字展开。适配器标明某个工具不支持按项目停用时，「在本项目停用」置灰，写「<工具> 不支持按项目停用」，旁边给「转成套装」；清单里写了也只对支持的工具生效，生效上下文如实显示。

**个人覆盖** `fangcun.local.toml` 是清单的子集：能加资产、能停用、能改版本约束，不能改 `targets`、`mode`、`budget` 这些全队共享的设置。个人加的项不进锁，记在本机 `~/.fangcun/state/`；停用写进工具的个人层文件，例如 `.claude/settings.local.json`；Codex 项目里没有不提交的配置，个人停用对 Codex 不生效，同步计划里写一条说明。另外只有个人覆盖能写 `[dev]`，列出在本机走开发模式的 skill（F2）：

```toml
# fangcun.local.toml
[dev]
skills = ["project-harness"]     # 本机直接链到 local:luyao-skills 的工作目录，改了立即可见
```

**套装文件** `~/.fangcun/bundles/<名称>.toml` 与清单同结构，多一节 `[bundle]`：

```toml
# ~/.fangcun/bundles/工程基线.toml
[bundle]
name        = "工程基线"
description = "TDD、提交规范、代码评审"

[skills]
tdd        = { source = "github:obra/superpowers", track = "main" }
git-commit = { source = "local:luyao-skills", pin = "0d81aa3" }
```

- 项目清单和套装声明了同一个资产时，项目清单优先（4.3 下层覆盖上层），锁里这一项不再标 `bundle`，「在哪一层声明」里套装那行划线。
- 套装文件只在本机。队友克隆项目后按锁还原：锁里已逐项记下套装展开后的每一项，没有套装文件也能同步。界面提示「本机没有套装『工程基线』」，可一键从锁生成套装文件。

### 7.5 安全

- 锁里的内容哈希在每次同步时校验，来源被篡改会被拦下。
- 升级差异里，脚本、hook、MCP 启动命令的变化单独高亮。
- 写入范围限定在已登记项目与已知工具配置目录。每次写入前快照。
  - 已知工具配置目录只认适配器声明的路径，包括全局层（`~/.claude/skills`、`~/.codex/config.toml` 等）。全局层的移除、降级、转成套装只对已收编进资产库的项开放，来源未知的项先收编（6.6）。共享文件按键合并，不整文件覆盖（4.6）。
  - 保留只读模式：设置里的「只读模式」开关和命令行的 `--read-only`，默认关闭。打开后一切写入用例直接拒绝，只写方寸自己的 `~/.fangcun/journal`，和 M0 一样。
- 因为需要较宽的文件访问，不走 Mac App Store 沙盒。采用公证过的安装包与 Homebrew 分发。v0.1 没有开发者账号，先发不签名的版本，见 9.3。
- 默认零遥测。

## 9. 风险与已定的事

### 9.1 风险

| 风险 | 应对 |
|---|---|
| 工具频繁改目录与格式 | 适配器数据化、可热更新、带回归样例 |
| 厂商原生机制逐步覆盖需求 | 坚持跨工具中立与项目级闭环，原生机制能用就用，不重复造 |
| 赛道拥挤 | 用只读的 M0 快速验证「生效视图」是否真是差异点 |
| 写错用户配置造成损失 | 预览、快照、所有权记录、按键合并。M0 完全只读 |
| 软链在个别工具或 Windows 上不可靠 | 适配器能力标记，自动退回「复制加哈希跟踪」 |
| Token 估算不准 | 始终标注为估算，重在相对比较而非绝对数值 |

### 9.3 界面遗留项的结论

第 6 节对照原型后留下八件原型没有覆盖的事，2026-11-14 逐条确认。正文已按结论改写。

| 事项 | 结论 |
|---|---|
| 更新中心放在哪 | 不单独做页面。入口是活动页的待处理项，处理在项目页检查器里，跨项目的批量升级在检查器里勾选受影响的项目 |
| 回滚较早的记录 | 后来的变更也动过同一批文件时，回滚预览里标出来，并要求先回滚后面的记录。不做自动合并 |
| CI 记录怎么回到本机 | 首版只记录本机运行的 `fangcun sync --frozen`，类型改称「校验」。远端 CI 的记录留到 V2 |
| 快照保留多久 | 默认 30 天，并且每个项目至少保留最近 20 个，可在设置里调整。过期后记录仍在，回滚按钮置灰 |

| 全局层要不要自己的清单 | 首版不做，按原型来 |
| 使用数据从哪一期开始读 | 提前到 M0。只读本机会话记录里的触发次数，不上传 |
| 只有一个项目用到时 | 在转成套装的变更计划里，只勾选一个项目时多给一个选项：不建套装，直接写进那个项目的清单 |

3. 活动页的类型和筛选芯片「CI」改成「校验」，触发方去掉 CI。
4. 活动页加「密钥」类型和筛选芯片。
5. 活动页的回滚预览，标出被后来变更动过的文件。
6. 活动页检查器，快照过期后回滚按钮置灰。
